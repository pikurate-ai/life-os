# 2026-10-20–21 후속 개발·검증

대상: `codex/life-os-v2`, 이전 `117bf4d` 이후의 사용성·백업·규칙 검사 변경. Windows / Node 24.19.0 / Chromium / 합성 데이터. 실제 iPhone Safari와 실제 사람 10명의 평가는 포함하지 않습니다.

## 코드 보완

- 모바일 모달 자체에 초기 포커스가 있을 때 Shift+Tab이 배경으로 벗어나던 경계를 수정했습니다. 뒤로 이동하면 마지막 버튼으로 순환합니다.
- 기억·사진·목표의 카테고리는 own-key로 검사합니다. `constructor` 등 상속된 이름을 UI 분류로 오인하지 않습니다. 알 수 없는 이전 분류의 표시와 필터 기준도 맞췄습니다.
- 사진 용량 계산은 편집 시작 시점이 아닌 현재 저장된 사진을 기준으로 합니다. 같은 파일 재선택·이전 링크 설명 편집과 비파괴 메타데이터 보존을 유지합니다.
- 오늘 목표 요약은 유효 범위의 완료 단계 인덱스를 중복 없이 계산합니다.
- 금고 CSV의 중복 판정에 notes를 포함해 다른 복구 메모가 유실되지 않게 했습니다. 부분 저장 뒤 기존 항목의 복호화가 끝날 때까지 재시도를 막습니다.
- 일기/금고 파일 미리보기도 미완료 가져오기 내용을 버릴 때 확인합니다.
- 누락된 `test:rules`와 Java 21 CI를 연결했습니다. Firestore 자체가 예약 ID를 invalid-argument로 거부하는 경우와 규칙의 permission-denied를 구분합니다.
- 정적 preview 서버가 `/review.html`을 `/review`로 제공하도록 보완했습니다. 실제 정적 빌드에서 404를 확인한 뒤 수정·재시작하여 정상 진입을 확인했습니다.

## 자동 검사

| 검사              | 결과                                                   |
| ----------------- | ------------------------------------------------------ |
| 포맷 검사         | 통과. 이전 5개 서식 오류 정리                          |
| TypeScript strict | 통과                                                   |
| 일반 자동 테스트  | 59개 통과 / 실패 0개                                   |
| 추가 도메인 검사  | CSV·일기·AES-GCM·잘못된 키·변조·고유 IV·난수 생성 통과 |
| 규칙 통합 검사    | **9개 통과 / 실패 0개**, 전용 로컬 emulator            |
| 일반 정적 빌드    | 통과. Next 15.5.28, `/`·`/review` export               |

기본 sandbox의 빌드가 `spawn EPERM`으로 중단되어 허용된 실행 권한으로 재실행한 결과입니다. 일반 테스트의 MODULE_TYPELESS_PACKAGE_JSON 경고는 남아 있지만 실패는 아닙니다.

규칙 검사는 `demo-life-os-qa`, `127.0.0.1:8085`만 사용합니다. 실제 Firebase 프로젝트·사용자 데이터·`.env.local`을 로드하지 않습니다. 공식 Adoptium Java 21 JRE를 체크섬 확인 후 제외 폴더 `.tools/temurin-21`에 준비했고, 검사 프로세스의 환경에만 적용했습니다. 시스템/전역 Java 설정은 바꾸지 않았습니다. 첫 실행은 예약 ID에 대한 테스트 기대 오류로 8/9였고, 기대 오류를 바로잡은 재실행에서 9/9였습니다. 거부 요청의 PERMISSION_DENIED 로그는 의도한 검사 결과입니다.

재현하려면 Java 21이 있는 환경에서 `npm run test:rules`를 실행합니다. 이 PC의 portable Java는 `.tools` 아래에만 있으므로 새 터미널에서 해당 bin을 PATH에 넣어야 합니다. CI는 Temurin Java 21을 준비합니다. 로컬 결과와 CI 성공 여부는 별개로 기록합니다.

## 실제 계정과 운영의 제한

Firebase CLI Google 로그인 성공을 확인했습니다. Windows CLI 종료 때 assertion 오류가 있었으나, 이후 인증된 상태에서 프로젝트 조회 명령을 실행했습니다. 프로젝트 목록은 0개, 기존 환경에 설정된 프로젝트의 apps:list는 실패했습니다. 현재 계정에서 기존 프로젝트를 조회하지 못한다는 근거이며 구체적인 IAM/삭제/API 설정 원인까지 확정한 것은 아닙니다.

기존 프로젝트에 접근 가능한 계정으로 연결할지, 별도 v2 프로젝트와 명시적 백업 이전으로 진행할지 사용자에게 질문했습니다. 답변 전에는 기존 DB·규칙·권한을 바꾸거나 새 프로젝트를 임의 생성하지 않습니다. 웹 앱 자체의 Google OAuth·운영 규칙 배포·실제 PC/iPhone 동기화는 미검증입니다. CLI 관리자 로그인과 앱 사용자 로그인은 별개입니다.

공개 테스트 배포와 CI의 후속 결과는 [현재 상태](../PROJECT_STATE.md)와 [배포 문서](DEPLOYMENT.md)를 확인하세요. 기존 공개 preview의 cloud-off 정책은 유지합니다.
