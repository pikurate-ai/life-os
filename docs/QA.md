# Life OS v2 검증 기록

검증일: 2026-10-16. Windows / Node.js 24 / Chromium 기반 Codex 브라우저에서 검증했습니다. 실제 사용자 데이터 대신 분리된 미리보기 공간과 합성 파일을 사용했습니다.

## 자동 검사

최종 자동 검사: 모델·이전·검색 개인정보 보호 테스트 **33개 통과**, 별도의 CSV·일기·Web Crypto·다중 금고 검사 통과.

- TypeScript strict 검사 통과.
- 결정적 병합, 삭제 tombstone, 계정별 저장 키 격리, 지속 큐, 오래된 탭의 승인 재생성, 시계 역행, 악성 미래 시각, 백업 구조·용량, 금고 평문 차단, 구버전 ID 안정성 검사 통과.
- CSV BOM·인용·줄바꿈·세미콜론·비밀번호 공백, 일기 날짜 분리·중복·잘못된 날짜 검사 통과.
- AES-GCM 왕복, 잘못된 키·변조 거부, 고유 IV, 보안 난수 비밀번호 생성 및 다중 금고 선택·격리 검사 통과.
- 일반 정적 export와 `GITHUB_PAGES=true`의 `/life-os` 정적 export 빌드 통과.

재현 명령:

```sh
npm run typecheck
npm test
npm run build
# PowerShell에서 Pages 경로 검사
$env:GITHUB_PAGES='true'
npm run build
npm run preview
```

개발 서버와 빌드는 같은 Next 출력 디렉터리를 사용하므로 동시에 실행하지 않습니다.

## 브라우저 검사

| 검사                                | 확인한 결과                                                          |
| ----------------------------------- | -------------------------------------------------------------------- |
| 오늘 화면 320/390/768/1024/1440px   | 가로 넘침 없음, 메뉴·카드·입력 영역 정상 표시                        |
| 재정·목표·읽기·사진·금고·설정 320px | 가로 넘침 없음                                                       |
| 모바일 달리기 저장                  | 4.5km / 30분 → 6분 40초/km 계산                                      |
| 달리기 수정                         | 5km / 30분 → 6분/km 계산                                             |
| 새로고침                            | 저장한 운동 기록 유지                                                |
| 같은 브라우저의 별도 창             | 수정 및 삭제가 다른 창에도 반영                                      |
| 긴 한글 제목·공백 없는 문자열       | 메모 저장·검색과 320px 모달 표시 정상                                |
| 일기 TXT 가져오기                   | 날짜 제목으로 2편 분리, 미리보기 후 실제 저장                        |
| 사진 업로드                         | 512px PNG를 약 19KB JPEG 사본으로 압축·저장·상세 보기                |
| 체험 → 개인 공간                    | 실제 개인 공간에 예시 기록이 들어오지 않음                           |
| 모바일 전체 메뉴 → 검색             | 포커스 트랩이 있는 모달 하나만 유지                                  |
| 생산 빌드 정적 경로                 | `/life-os/`, manifest, PNG 설치 아이콘, service worker 모두 HTTP 200 |
| 정적 서버 중단 후 새로고침          | service worker의 앱 셸로 재실행                                      |
| 정적 서버 중단 중 기록              | 메모 저장 → 새로고침 → 기록 확인 성공                                |
| 브라우저 콘솔                       | 검사한 흐름에서 오류·경고 없음                                       |

테스트 중 생성한 운동·메모·일기·사진은 미리보기 공간에서 정리했습니다. 실제 사용자의 기존 저장 데이터나 CSV는 읽지 않았습니다.

## 검증의 범위

별도 창 검사는 같은 브라우저의 로컬 동기화 검사입니다. 실제 데스크톱과 iPhone 사이의 Firebase 동기화를 확인한 것으로 간주하지 않습니다. 실제 OAuth 로그인, Firebase 운영 규칙 배포·에뮬레이터 권한 테스트, iOS Safari/Android 실기기, 네이티브 앱 서명·스토어 심사, 상업 서비스의 개인정보·결제·계정 삭제는 별도 운영 검증이 필요합니다.

현재 버전은 일반 기록을 브라우저 저장소에 보관하며, 암호금고만 별도 종단간 암호화합니다. 사진은 압축 사본과 용량 제한을 사용합니다. 자세한 운영 전제는 [배포 문서](DEPLOYMENT.md)에 있습니다.
