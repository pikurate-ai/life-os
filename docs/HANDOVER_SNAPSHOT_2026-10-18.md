## 3. 공유 모달·날짜 입력 변경

### 작성 중 내용 보호

- `Modal`에 `dirty?: boolean`을 추가했습니다. 편집 화면은 실제 초기값과 현재 초안의 차이를 전달합니다.
- X·Escape·배경 클릭과 `ModalCloseButton`은 같은 닫기 요청을 사용합니다. 변경이 있으면 같은 dialog 안에서 **계속 작성 / 버리고 닫기**를 확인합니다.
- 확인 중 원래 폼을 숨겨 포커스 대상에서 제외하고 초안 자체는 유지합니다. 저장 성공에 따른 닫기는 이 확인을 거치지 않습니다.
- 이 가드는 모달 닫기에 대한 보호입니다. 브라우저 새로고침·강제 종료에도 초안을 자동 저장한다고 약속하는 기능은 아닙니다.

### 작은 화면과 키보드

- `visualViewport`의 크기와 offset을 모달 배경의 CSS 변수로 반영하고 resize·scroll을 따라갑니다.
- 모달 최대 높이·내부 스크롤·안전 영역 여백, 폼의 `min-inline-size: 0`, 날짜·시간·월 입력의 폭 제한과 appearance 보완을 추가했습니다.
- 모바일 입력 글자를 16px로 유지하고 좁은 화면에서는 dialog에 초기 포커스를 두어 불필요한 자동 키보드 열림을 줄입니다.
- 실제 iOS Safari의 키보드, 스크롤 보정, 네이티브 날짜 선택기를 검증한 것으로 간주하면 안 됩니다.

### 포커스와 배경 스크롤

독립 소스 검토 중 발견한 다음 문제를 주 작업자가 보완했습니다.

1. 초기 discard 상태 effect가 모달로 먼저 포커스를 옮겨 원래 열기 버튼을 잃던 문제: 확인 상태가 실제 전환됐을 때만 포커스를 바꾸도록 수정.
2. drawer와 모달이 잠시 겹치며 `body.overflow`를 서로 잘못 복구하던 문제: 공통 참조 계수 `lockScroll`을 사용하고 마지막 소유자가 닫힐 때만 복구.
3. drawer 정리 후 모달 밖으로 포커스가 튀거나 제거된 버튼으로 복원하던 문제: 활성 dialog와 연결된 요소 여부를 검사하고 모달에는 안전한 포커스 복귀 대상을 사용.

스크롤 잠금 테스트는 drawer/모달의 두 해제 순서와 중복 해제를 다룹니다. 실제 Safari에서의 스크롤 잠금과 포커스 복귀 확인은 여전히 필요합니다. 개발 환경의 Next 표시가 하단 메뉴를 가리는 사례를 줄이기 위해 `next.config.ts`에 `devIndicators: false`도 추가했습니다.

다음은 합성 역할 관점에서 발견한 문제를 바탕으로 한 구현 요약입니다. 사람을 모집해 실시한 사용자 연구 결과가 아닙니다.

| 화면 | 주요 개선과 보존 원칙                                                                                                                                                                                                                |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 기억 | 긴 메모를 수정 폼 없이 읽는 전체 보기 추가. 민감 메모의 화면 가림·명시적 보기·visibility 변경 시 다시 가리기 유지. 내용 복사는 사용자가 누른 경우에만 수행. 저장 후 검색·필터가 새 기록을 숨기지 않게 정리                           |
| 가계 | 실제 기록의 카테고리로 통계를 계산해 이전 분류 누락 방지. 편집 선택지에 기존 분류 유지. 0원 자산 잔액 수정 허용. 거래 저장 후 해당 월·전체 구분으로 이동. 긴 거래·액션 줄바꿈 보완                                                   |

| 사진 | 실패한 파일을 같은 이름으로 다시 선택할 수 있게 입력 초기화. 이전 원격 사진 링크만 있는 기록도 제목·설명을 편집 가능. 외부 이미지를 자동 요청하지 않고 명시적 링크 열기 제공. 이미 한도를 넘은 보관함도 용량을 늘리지 않는 수정 허용 |
| 목표 | 완료 해제의 명시적 상태 유지. 진행 재개 시 기존 단계 기록을 지우지 않음. 같은 이름의 단계를 편집해도 하나의 완료가 여러 단계에 중복 적용되지 않도록 대응. 저장한 상태의 필터로 이동                                                  |
| 오늘 | 선택 날짜를 일기로 전달. 운동 저장 단위는 분을 유지하면서 요약·툴팁은 분·초로 표시. 자료 카드는 검증한 원문 열기. 할 일·루틴의 공백 입력과 저장 오류 안내, 루틴 삭제 확인 추가                                                       |

셸의 빠른 기록에는 공백 제목·잘못된 URL·저장 실패에 대한 폼 오류 표시가 추가되었습니다. 전체 검색에서 일기를 열 때도 해당 날짜를 전달합니다. `WorkspaceShell`은 데이터 소유 공간이 바뀌면 초안과 dialog를 폐기하는 계정 격리 동작을 유지합니다.

## 5. 레이아웃 리뷰 화면의 범위

[review/page.tsx](../src/app/review/page.tsx)는 앱을 실제 iframe에 표시합니다.

- 기본 모바일 내부 크기는 **390×844**, 데스크톱은 **1440×900**입니다.
- 가로 보기와 짧은 높이 모의를 제공하고, 외부 프레임만 배율 조정해 내부 CSS viewport를 유지합니다.
- `ResizeObserver`로 가용 폭에 맞추며 모바일/데스크톱 선택은 localStorage에 보관합니다.
- 이는 화면 배치를 보는 도구입니다. 짧은 iframe 높이는 실제 iOS 키보드의 VisualViewport offset·네이티브 날짜 UI를 재현하지 않습니다.
- iframe은 같은 앱·origin을 엽니다. 별도의 격리된 가짜 데이터 서버가 아니므로 기록 테스트는 예시/합성 데이터 공간에서 진행해야 합니다.

## 8. CI의 Firestore 규칙 테스트 연결이 미완성

[ci.yml](../.github/workflows/ci.yml)에 `firestore-rules` job이 추가되어 `npm run test:rules`를 호출하지만, 현재 [package.json](../package.json)의 scripts에는 **`test:rules`가 없습니다.** 그대로 CI를 실행하면 해당 단계가 실패할 수 있으며 연결 완료로 간주하면 안 됩니다.

[규칙 통합 테스트 파일](../tests/firestore-rules.integration.mjs)은 공식 rules SDK와 전용 로컬 에뮬레이터를 사용하도록 작성되어 있습니다. 프로젝트 `demo-life-os-qa`, loopback `127.0.0.1:8085`만 허용하며 `.env.local`이나 실사용 프로젝트를 불러오지 않는 계약입니다. 이 파일은 의도적으로 `*.test.mjs` 이름이 아니므로 일반 `npm test`의 59개 통과가 해당 규칙 검사의 실행을 뜻하지 않습니다.

다음 작업자는 전용 에뮬레이터 실행·환경 계약에 맞는 `test:rules` script를 연결하고, 실제 실행 결과와 CI 결과를 따로 기록해야 합니다. 이를 위해 실사용 Firebase 프로젝트나 사용자 데이터를 사용하면 안 됩니다. 현재 파일 작성만으로 owner/other/anonymous 권한 격리가 검증됐다고 보고하지 마세요.

## 9. Firebase 운영 연결은 아직 별도 작업

- Google OAuth의 실제 프로젝트 설정·허용 도메인·계정 권한·Safari 로그인 성공을 검증하지 않았습니다.
- Firestore 규칙의 운영 배포와 실사용 계정의 권한 테스트를 검증하지 않았습니다.
