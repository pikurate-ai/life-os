# iPhone Google 로그인 복귀 수정 — 2026-10-21

## 문제와 판단 근거

사용자는 iPhone에서 Google 계정 선택 후 로그인 버튼으로 되돌아오는 현상을 반복 제보했습니다. 앞선 데모 모드/리디렉션 결과 콜백 수정만으로 해결되지 않았습니다. 기존 자동 검사 59개는 OAuth 왕복을 검사하지 않았으므로 통과만으로 해결을 선언하면 안 됩니다.

GitHub Pages의 앱과 `firebaseapp.com`의 인증 도우미는 다른 출처였습니다. Firebase는 Safari 16.1 이상 등 제3자 저장소를 차단하는 브라우저에서 이 구조의 리디렉션 인증에 추가 조치가 필요하다고 설명합니다. 실제 기기의 내부 추적 로그는 없으므로 사용자 증상의 모든 원인을 확정한 것은 아니지만, 확인된 구조적 위험을 제거했습니다.

공식 근거: [리디렉션 로그인 권장사항](https://firebase.google.com/docs/auth/web/redirect-best-practices).

## 현재 구조

- 권장 앱: **https://life-os-563cd.firebaseapp.com/**
- 로그인 바로 열기: **https://life-os-563cd.firebaseapp.com/?page=settings**
- 모바일/웹 리뷰: **https://life-os-563cd.firebaseapp.com/review**
- Firebase 프로젝트는 `life-os-563cd`, Firestore 위치는 사용자가 승인한 서울 `asia-northeast3`입니다. 기존에 설정한 Google 공급자와 UID별 규칙을 사용합니다.
- 앱과 `/__/auth/handler`, `/__/auth/iframe`을 같은 HTTPS 출처에서 제공합니다. 별도 API 키나 새 OAuth 클라이언트를 만들지 않았습니다.
- `firebase.json`의 Hosting은 `out/`만 게시합니다. `npm run build:firebase`는 대상 프로젝트/인증 도메인과 루트 경로를 검사합니다. 배포는 `firebase deploy --only hosting --project life-os-563cd`입니다. 이 배포로 DB/규칙/요금제를 변경하지 않습니다.
- 모바일 독립 앱은 같은 출처에서 리디렉션합니다. 데스크톱은 클릭 즉시 팝업을 열며, 같은 창 로그인도 선택할 수 있습니다. Firebase SDK의 기본 지속 인증 저장소를 사용하며 팝업 전 `await setPersistence`를 제거했습니다.
- GitHub 등 다른 출처와 리뷰 iframe에서는 독립 로그인 주소를 엽니다. iframe `allow`로 Safari 저장 제한이나 Google 프레임 정책을 해결하려는 경로는 제거했습니다.
- 리디렉션 표식은 sessionStorage의 시작 시각 하나뿐입니다. 15분 후 만료되며 단회 소비합니다. 계정·토큰·인증 코드는 포함하지 않습니다. 시도 후 결과도 복원 계정도 없으면 명시적인 복구 오류를 표시합니다.
- Strict Mode에서도 결과 처리를 한 번 공유하고 정리된 효과는 상태를 바꾸지 않습니다. sessionStorage 표식 읽기 오류가 나도 실제 인증 리스너 등록을 계속합니다.
- 서비스 워커는 `/__/`를 가로채거나 오프라인 앱 화면으로 대체하지 않습니다. 앱 셸 캐시 버전은 `v2.0.2`입니다.

## 실제로 확인한 범위

1. 포맷·타입 검사, 일반 테스트 **73개**, 추가 CSV/일기/암호화 검사, 일반 정적 빌드와 Firebase 빌드 통과. 인증 경로·악성 도메인·프레임·표식 만료/손상·누락 결과에 대한 13개 검사와 인증 경로 SW 제외 검사를 추가했습니다.
2. Firebase Hosting 배포 성공. 앱·리뷰·manifest·SW와 `/__/auth/handler`, `/__/auth/iframe`, `/__/firebase/init.json`이 HTTPS 200을 반환했습니다. 공개 인증 설정의 허용 도메인에도 Firebase 앱 주소가 있습니다.
3. Codex Chromium 독립 탭에서 **같은 창 로그인 → Google 기존 계정 선택 → 원래 앱 복귀 → Google 계정/로그아웃/동기화 완료 표시**를 확인했습니다. 첫 시도에서는 네트워크 오류가 보였고 재시도에서 성공했습니다. 재시도가 필요했던 사실을 생략하지 않습니다.
4. 새로고침 후 로그인 유지와 같은 계정 작업공간을 확인했습니다.
5. 새 Firebase 주소에서 확인용 메모 1개를 저장했습니다. 별도 출처인 기존 GitHub 앱의 모바일 390×844 프레임에서 같은 메모 수신을 확인했습니다. 그 프레임에서 본문을 수정하고 새 Firebase 탭에 수정분이 도착하며 동기화 완료가 되는 것을 확인했습니다. 두 출처는 브라우저 로컬 저장소를 공유하지 않습니다.

이는 **실제 iPhone Safari/홈 화면 앱의 성공 확인을 대신하지 않습니다.** 오른쪽 리뷰는 Chromium의 CSS 크기 모의입니다. 새 권장 주소에서 실제 iPhone 왕복·키보드·홈 화면 재실행을 사용자가 확인해야 합니다.
